## Phase 2: Pinned snapshot

**Goal:** Write a deterministic, versioned snapshot and capped logs to a durable run
directory.

**Files:** `src/pry/intake/snapshot.py`, `tests/intake/test_snapshot.py`

**Steps (TDD):**
1. Tests:
   - `new_run_dir(out=None, home=tmp_path)` → `tmp_path/.pry/runs/<id>` with 0700.
   - `write_snapshot(run_dir, data)` writes `snapshot.json` atomically, 0600.
   - Same data → byte-identical JSON (sorted keys, indent 2).
   - `write_log(run_dir, "build.log", data)` caps at 1 MiB and sets 0600.
   - Snapshot schema has `version`, `sandbox_id`, `created_at`, `target`, `project`,
     `sandbox`, `result`.
   - A failure snapshot has `result.status == "failed"` and the cause.
2. Implement:
   - `new_run_dir(out, home=None) -> Path`; `--out` is the exact run dir.
   - `write_snapshot(run_dir, snapshot) -> Path` via `.tmp` + `os.replace`.
   - `write_log(run_dir, name, data) -> Path`, truncating to 1 MiB with a marker.
   - `snapshot_id()` → `pry-` + 12 hex chars.
   - `utc_now()` → ISO 8601 `Z`.
3. Run tests.

**Validation:** `uv run pytest tests/intake/test_snapshot.py` passes.

**Commit:** `feat(intake): write pinned snapshots and capped logs`

## Phase 3: Docker runner

**Goal:** All Docker calls live behind one wrapper with testable argument construction
and a fake command runner.

**Files:** `src/pry/intake/docker.py`, `tests/intake/test_docker.py`

**Steps (TDD):**
1. Tests for `DockerRunner` using a `FakeCommandRunner`:
   - `available()` calls `docker info`; nonzero → `False`.
   - `ensure_image("node:22-bookworm-slim")` calls `docker pull`, then
     `docker image inspect --format '{{index .RepoDigests 0}}'`; returns the digest.
   - `build(...)` args include `--rm`, `--network=bridge`, `--cap-drop=ALL`,
     `--security-opt=no-new-privileges`, `--read-only`, `--tmpfs=/tmp:rw,exec`,
     `--user=<uid>:<gid>`, memory/CPU/PID limits, `-v <workspace>:/app`, `-w /app`,
     `-e HOME=/tmp`; the image and command come last.
   - `start(...)` args include `-d`, `--name <id>`, `--network=none`, the same security
     flags, `-e PORT=<port>`, and the start command.
   - No args contain `docker.sock`, `--privileged`, `--pid=host`, `--ipc=host`,
     `--uts=host`, or `--device`.
   - `build` nonzero or timeout → `BUILD_FAILED`.
   - `start` nonzero → `START_FAILED`.
   - `wait_ready` polls `exec`; success returns; container exited → `START_FAILED`;
     deadline → `READY_TIMEOUT`.
   - `logs` returns bytes; `remove` tolerates "no such container".
2. Implement:
   - `CommandResult(returncode, stdout, stderr, timed_out)`.
   - `SubprocessRunner.run(args, timeout) -> CommandResult`.
   - `DockerRunner(runner=None, uid=None, gid=None, memory="2g", cpus="2",
     pids=512)`.
   - `readiness_command(kind, port)`: Node uses `fetch`, static uses
     `urllib.request` and treats `HTTPError` as ready.
   - All Docker calls use `subprocess` with `timeout`; map errors to causes.
3. Run tests.

**Validation:** `uv run pytest tests/intake/test_docker.py` passes; no Docker calls.

**Commit:** `feat(intake): wrap docker with security flags and readiness checks`

## Phase 4: Sandbox orchestration and cleanup

**Goal:** One `intake()` operation with a guaranteed cleanup path.

**Files:** `src/pry/intake/sandbox.py`, `tests/intake/test_sandbox.py`

**Steps (TDD):**
1. Tests with a `FakeDocker` and a temp repo:
   - Missing path → `REPO_NOT_FOUND`, no run dir.
   - Unsupported project → `UNSUPPORTED_PROJECT`, no container.
   - Docker unavailable → `DOCKER_UNAVAILABLE`, no container.
   - Build failure → `BUILD_FAILED`, `remove` called, workspace deleted, failure
     snapshot written with the cause.
   - Start failure / readiness timeout → matching cause, cleanup.
   - Success → `start` called with `--network=none`; snapshot `status: ready`; `remove`
     called; workspace deleted.
   - `keep=True` → `remove` not called; workspace remains; cleanup command printed by
     the CLI.
   - The original repo is unchanged (tree hash before/after).
   - SIGINT (`KeyboardInterrupt` from build) → `INTERRUPTED`, cleanup.
2. Implement `intake(path, *, out=None, keep=False, port=None, timeout=None,
   docker=None) -> IntakeResult`:
   - Validate path; copy; detect; ensure image; build if needed; start; wait ready;
     write snapshot; return.
   - Wrap in `try/except/finally`; write a failure snapshot when possible; always
     remove the container unless `keep`; always delete the workspace unless `keep`.
   - Build timeout default 600s; readiness default 60s.
   - Record git state from the original before copying.
   - Expose `IntakeResult(snapshot_path, snapshot, container_id, workspace, kept)`.
3. Run tests.

**Validation:** `uv run pytest tests/intake/test_sandbox.py` passes; cleanup assertions
cover every failure path.

**Commit:** `feat(intake): boot the sandbox and guarantee cleanup`

## Testing Strategy

- **Unit, offline:** project detection, copy exclusions, tree hash, snapshot bytes,
  Docker arg construction, readiness command, cleanup paths, CLI output.
- **Fakes:** `FakeCommandRunner` returns scripted `CommandResult`s; `FakeDocker`
  implements the runner methods used by `intake`. No `subprocess` call leaks.
- **Integration, opt-in:** `PRY_DOCKER_TESTS=1`, marker `docker`, local fixtures only.
  Never a third-party target. Each test removes containers in `finally`.
- **Isolation assertions:** inspect the recorded argv for `--network=none`,
  `--cap-drop=ALL`, `--security-opt=no-new-privileges`, `--read-only`, `--user`,
  limits, and the absence of socket/privileged/host namespaces.
- **Host integrity:** snapshot the fixture's `git status` and tree hash before/after;
  assert unchanged.

## Environment & Secrets

- Docker CLI and daemon are required only for integration tests and real intake.
- No new env vars. `PRY_DOCKER_TESTS=1` enables integration.
- The temp copy may contain `.env` or secrets; it is deleted unless `--keep`. Logs and
  snapshots are 0600 and local-only. Never print file contents.
- Do not mount the Docker socket. Do not use the host network.

## Edge Cases & Error Handling

| Case | Behavior |
|---|---|
| Missing path / file | `REPO_NOT_FOUND` |
| Empty dir / no start script / yarn or pnpm | `UNSUPPORTED_PROJECT` |
| Invalid `package.json` | `UNSUPPORTED_PROJECT` |
| Docker daemon down | `DOCKER_UNAVAILABLE`, no temp container |
| Copy error | `COPY_FAILED`, cleanup |
| Build nonzero / timeout | `BUILD_FAILED`, cleanup |
| Container exits before ready | `START_FAILED`, cleanup |
| Readiness deadline | `READY_TIMEOUT`, cleanup |
| SIGINT | `INTERRUPTED`, cleanup, exit 1 |
| Snapshot write error | `SNAPSHOT_FAILED`, cleanup |
| `--keep` | container and workspace remain; print cleanup command |
| Host repo dirty | copied as-is; `git_dirty: true`, tree hash of the copy |
| Non-git repo | `git_commit: null`, `git_dirty: null`, `is_git: false` |
| Symlink in repo | copied as a link, not followed; hashed by target string |
| Large repo | excluded generated trees; future size cap |
| Port override | sets `PORT` and readiness port; app must honor it |

## Agent Execution Notes

- **TDD every phase.** Write the test file first, run it red, implement, run green.
- **Commit per phase** with the messages above. Never add `.venv`, temp copies, or
  Docker artifacts.
- **Checkpoints for review:** after Phase 3 (Docker flags), after Phase 4 (cleanup),
  and after Phase 5 (CLI).
- **Likely debugging:** Docker UID/file ownership on macOS, `npm ci` cache writes,
  `docker exec` readiness quoting, container removal races, and `--keep` cleanup.
- **Ask before proceeding if:** a test needs a third-party target, a Docker flag would
  weaken isolation, or a requirement contradicts the PRD.
- **Do not:** add probes, live URL intake, Python/yarn support, or claim the sandbox is
  a kernel-level security boundary.
