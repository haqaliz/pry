## Phase 0: Config and probe

**Files:** `src/pry/probe/database_rules.py`, `tests/probe/test_database_rules.py`

**Steps (TDD):**
1. Tests:
   - Config: 0600, provider, URL, paths, marker, anon key; reject 0644/missing/invalid JSON,
     absolute/Firebase-query paths, HTTP non-loopback, userinfo.
   - Firebase: marker string/`{"marker": ...}`; data non-empty → EXPOSED; empty/null/non-JSON
     → NOT_REPRODUCED; 401/403/404 → NOT_REPRODUCED; 5xx/transport → UNVERIFIED.
   - Supabase: `apikey` sent; marker row; data rows; key redacted; same verdicts.
   - Marker mismatch/denied/transport raises `DatabaseError` with a stable cause and never
     requests the data path.
   - Same-origin checks; 4 KiB cap.
2. Implement `database_rules.py`.
3. Run tests.

**Commit:** `feat(database): check provider rules with a marker`

## Edge Cases

| Case | Behavior |
|---|---|
| Marker matches, data non-empty | EXPOSED |
| Marker matches, data empty | NOT_REPRODUCED |
| Marker mismatch | exit 2, no data request |
| Marker 403/transport | exit 2, no data request |
| Data 403 | NOT_REPRODUCED |
| Data 5xx/transport | UNVERIFIED |
| Supabase key | redacted everywhere |
| HTTP non-loopback | exit 2 |
| Default scan | unchanged |

## Definition of Done

- AT1–AT9 pass; loopback integration passes; default suite offline.
- EXPOSED proof verifies; key/config path absent.
- Docs state the marker limitation and one-path scope.
